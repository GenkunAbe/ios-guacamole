# m1973: the sweet port on the Meizu 16s Pro (SM8150 / SD855+)

Same plan as guacamole, one board over: XNU boots from the stock ABL,
reuses ABL's continuous-splash framebuffer, runs the iPhone X iOS 16.7.16
userland. Status: **board profile written and audited against the phone's
own stock trees; first kernel build in CI.**

## Board facts (m1973)

Sources: the phone's own stock trees — the FDT inside the Flyme 8.1.5.3A
`update.zip` `boot.img` (model "Qualcomm Technologies, Inc. SM8150 v2
SoC", msm-id <0x153 0x20000>) and its dtbo overlays (root model
`M1973(MTP),meizu,board-id = <2 3>`; panel and touch live in the dtbo,
not the base DTB). Audit: `tools/fdt-audit.py <stock boot FDT> --device
m1973` reports **17/18** — every SoC block matches; the one BAD line is
the `/memory` low bank, which the stock DTB does not carry (ABL injects
/memory at boot; the shim probe report will print the live banks).

| Area | Value | Confidence |

## What differs from guacamole

- Panel: 1080x2232 (splash-cropped from the iPhone X's 1125x2436, like
  sweet) instead of 1440x3120 letterboxed; stride 4320.
- Touch: Goodix GT9886 instead of Samsung S6SY761 — both on SE17 @
  0xc80000 and both on `ldoa17`, but no Goodix transport driver yet, so
  `SWEET_DEV_TOUCH_SEC 0` compiles the Samsung transport out.
- Volume-down is PON RESIN (sweet-style), not a second PMIC GPIO.
- No PM8009 on the board (guacamole's PMIC SIDs list drops 0xa).
- Bootloader: Meizu's ABL has no `fastboot boot` response while locked;
  the port keeps images flashable (`fastboot flash boot`/`boot_b`) once
  unlocked. Probe boots use the flash path.

## Build

Everything follows GUACAMOLE.md with `m1973` in place of `guacamole`:

```sh
# kernel: GitHub Actions -> xnu workflow, machine_config=M1973
#         -> artifact kernel.development.m1973
python3 tools/mkadt.py shim/out/m1973.adt --device m1973 --highmem
python3 tools/mkpayload.py xnu/out/kernel.development.m1973 shim/out/m1973.adt \
    shim/out/payload-m1973.bin --cmdline '... (see GUACAMOLE.md) ...'
BOARD=m1973 DTB=<stock Meizu boot DTB> shim/build.sh ../shim/out/payload-m1973.bin
```

The stock Meizu boot DTB: unpack the official `update.zip` `boot.img`,
`tools/unpack_bootv2.py` (the appended QCDT blob at kernel end, FDT magic
d00dfeed).

## Unlock note (Meizu-specific)

The stock ABL answers `flashing get_unlock_ability` with **0**; the
standard unlock-permission byte lives in the `frp` partition. Community
flow: 9008 (EDL) with the Meizu `prog_firehose_ddr.elf` from the factory
flash package writes `frp`, then `fastboot flashing unlock` (volume-key
confirm) follows the standard AOSP path. `fastboot boot` availability is
re-tested after unlock.
